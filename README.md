# ICND1065L LED Panels with Raspberry Pi Pico / Pico W

PIO/DMA firmware for 64×32 RGB ICND1065L panels: USB video and GIF streaming,
an autonomous Wi-Fi solar dashboard, authenticated OTA, and experimental
four-panel 256×32 text/arrow tests. Documentation is primarily Bulgarian.

**Това не е универсален HUB75 драйвер.** ICND1065L изисква специална
инициализация, LAT команди и непрекъснато сканиране. Еднаква букса не означава
съвместим протокол. Реално използваният SCLK е **1,5625 MHz**, не 20 MHz.

## Състояние

| Вариант | Състояние |
|---|---|
| Един панел, статична геометрична фигура | Визуално потвърден на YD-RP2040 |
| Един панел, USB изображения/GIF | Работи; запазени са и експериментите за артефакти |
| Един панел, Solar на Pico W | Визуално потвърден; Wi-Fi, настройки, OTA и кеширани измервания |
| Четири панела, текст | Всички получават данни; наблюдавани са цветни артефакти, още се изследват |
| Четири панела, локално завъртане 180° | Firmware потвърден, PIO/DMA errors=0; геометрията се проверява визуално |
| Четири панела, движеща се стрела | Изпълнен тест с errors=0; очаква се окончателно визуално потвърждение |

**Нулевият брояч за грешки не доказва правилна картина.** Четирипанелните
варианти са диагностични, не завършен драйвер за произволно видео 256×32.
Първият опит за DMA от flash не премина OTA проверката и е заменен с RAM вариант.

## Варианти и файлове

Общото приложение е [pico/main.cpp](pico/main.cpp). Отделните режими се
избират при компилация, а не се презаписват взаимно в изходния код.

| Команда | Получен режим |
|---|---|
| `python build.py usb` | USB видео за един панел, оригинално обновяване |
| `python build.py usb-no-config` | Без повторен запис на конфигурацията при кадър |
| `python build.py usb-no-gap` | Без повторна конфигурация и без паузите |
| `python build.py usb-continuous` | Експеримент с непрекъснат scan/LAT prefix |
| `python build.py solar` | Solar + настройки + OTA + `/api/readings` |
| `python build.py chain-text` | Текст на четири панела, всеки завъртян на 180° |
| `python build.py chain-unrotated` | Същият тест без локалното завъртане |
| `python build.py chain-arrow` | Еднократна стрела през четирите панела |

Архиви на действителния по-стар код: [статичен 0.1](snapshots/static-0.1/)
и [USB 0.2](snapshots/usb-0.2/). Те са експортирани от оригиналните Git
комити, без готови firmware файлове. [Описание на вариантите](docs/VARIANTS_BG.md).

## Свързване

| Панел | HUB75 контакт | Pico GPIO |
|---|---:|---:|
| R1, G1, B1 | 1, 2, 3 | GP2, GP3, GP4 |
| R2, G2, B2 | 5, 6, 7 | GP5, GP6, GP7 |
| A, B, C | 9, 10, 11 | GP8, GP9, GP10 |
| S / CLK | 13 | GP11 |
| L / LAT | 14 | GP12 |
| OE | 15 | GP13 |
| GND | 4, 8, 12, 16 | обща земя |

Всеки панел получава отделно стабилизирано **5 V** захранване. Лентовият кабел
не захранва панелите. За четири панела: OUT → IN → OUT → IN. Следвайте GPIO
номерата, не само физическото положение на пиновете. Не подавайте 5 V към Pico
GPIO и не свързвайте едновременно изходите на FPGA и Pico. Разместване на
кабели само при изключено захранване. Работата с директни 3,3 V сигнали е
потвърдена за конкретната постановка, не гарантирана за всяка дължина кабел.

## Компилиране и инсталиране

Следвайте [BUILD_BG.md](docs/BUILD_BG.md): Pico SDK, Arm toolchain, CMake,
Ninja и Python. Няма публикувани персонализирани UF2/.panel файлове, защото
могат да съдържат пароли и ключове. Всеки изгражда образ със собствени данни.

USB-only: компилирайте и копирайте `pico_panel.uf2` върху BOOTSEL диска.
Solar/четири панела: при първа инсталация използвайте **`panel_initial_usb.uf2`**,
който включва bootloader. За следващи обновявания се използва подписаният
`pico_panel.panel`. Не смесвайте USB-only образ и OTA приложение.

## Използване

```powershell
python -m pip install -r requirements.txt
python pico/usb_video.py --status
python pico/usb_video.py your-animation.gif --rotate 90 --loops 0
python pico/usb_video.py --playlist first.gif second.gif --seconds 10 --loops 0
```

Стрелата се пуска след потвърден старт на `chain-arrow` с празна POST заявка:
```sh
curl -X POST -H "Authorization: Bearer $K" http://PANEL_IP/api/test/arrow
```
Стои 2,5 секунди на първия логически панел, преминава веднъж и оставя черен
екран. Повторна заявка повтаря теста. Endpoint-ът съществува само в този режим.

Solar не използва публичен облачен API: получава пасивно **TZSP/UDP 37008**
от MikroTik с огледално копие на съвместимия Huawei SDongle трафик.
Източникът и филтрите трябва да бъдат адаптирани за друга инсталация.

```sh
curl -H "Authorization: Bearer $K" http://PANEL_IP/api/readings
```
Измерванията са от кеш, в W и проценти, с `null` при липса и `stale=true`
след 120 секунди. Отчетите могат да идват през няколко минути. `ts` е времето
от източника, не проверен чрез NTP часовник. [Пълно API описание](pico/READINGS_API.md).

HMAC ключа или персонализирания firmware. [SECURITY.md](SECURITY.md).
